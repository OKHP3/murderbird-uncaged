The old writer assigned scene-linear target numbers into an image marked sRGB, then saved those same numbers as PNG channel values. In Blender 5.2.1 LTS the known (.050, .073, .040) swatch produced PNG bytes (13,19,10), whose sRGB decode is about (.0040,.0065,.0030). The corrected writer applies the piecewise IEC sRGB transfer explicitly using stdlib PNG encoding, producing bytes (63,76,56), decoded about (.0497,.0723,.0395). It reloads FILE images, sets color sRGB / ORM Non-Color, and packs them. Blender image API channel values alone do not establish shader linear values: the FILE API returns the encoded values here. The emission render and raw PNG evidence establish the actual transfer.

`byte-evidence.json` reads PNG and GLB data separately from Blender. Seven GLB color image payloads have exactly the external PNG RGB bytes. The PNG compressed-container hashes can differ because the glTF exporter rewrites PNG containers; RGB pixel hashes match. GLB materials and swatch emission evidence are recorded without claiming a browser screenshot.

## Protected optical routing correction

The integration smoke exposed an inherited `cg2bFamily` tag on new optical/glass graphs after their texture nodes had been cleared. The initial finish04 API honored only that stale material tag. The corrected API now honors `cgSurfaceFamilies` by ordered slot index, skips `protected-optic`, `protected-glass` and `cg2aPreserveMaterial` before inspecting texture nodes, and keys its replacement cache by material plus routed family. Malformed unprotected family graphs raise a contextual error containing object, slot, family, material and missing texture labels. Explicit routing counts and unknown family names are validated.

`protected-graph-smoke.py` directly verifies material pointers, node-tree pointers, node pointers, socket values, links and custom properties remain identical for stale-tag protected slots; also verifies malformed unprotected rejection and ordered differing families sharing the same stale-tag source material. The smoke is synthetic and does not replace actual integrated native/browser review. Future receipts summarize preserved slots as count, deterministic SHA-256 of all ordered rows, and first twenty rows. All prior frozen receipts in this directory remain byte-unchanged.
