# Independent composition check review

Review scope: read-only inspection of `scripts/compose-alignment-native.py`, the pinned transfer contract, the saved native/runtime outputs, the transfer-record dump, the composition log, and the binary/JSON parity comparison. I did not rerun Blender or modify the composer. This audit concerns only the local `composition-check` derivative; it does not establish a final V8 model or owner/artistic acceptance.

The selective transfer is narrowly specified and the implementation follows that allowlist: 12 `Digit inner link` mesh-data replacements and 12 named proximal/distal dorsal guards, all sourced from native SHA-256 `5d8d101f…bedfde54` into frozen V7 base SHA-256 `a8fccaf0…c75ed3f`. The composer checks source object sets, limits replacements to mesh data, requires additions to map to existing pivot owners, restores each addition's saved basis and parent inverse, and compares the full scene snapshot after native reload. The generated inventory contains 699 mesh parts, 51 pivots, and 462 retained control curves. The output remains under `assets/audit/alignment-composition-check/native/`; the application still points to V7.

Material remapping is explicit. Each source slot is recorded by name, the imported slot shader signature is checked against the base material of that name, and the slot is replaced with the original base material datablock in the same order. The composer also compares the full material-name/signature map. It retains the two existing unused datablocks `Neutral / edge.001` and `Neutral / plate.001` with `use_fake_user=True`; the receipt states this authoring-metadata exception. This flag change is real, but the files confirm the intended scope: no shader redesign or material-slot reassignment is claimed.

The native/reopen/export path is appropriately separated. `export_from_reopened_native` reopens the saved native, checks its complete scene snapshot and modifier signatures, applies modifiers and batches only in that in-memory export copy, then checks pivot world matrices after batching. The native file is not saved again after export. The source and output hashes in the inventory agree with the actual files. The parity receipt binds the attempt-03 runtime GLB `574d9ca4…3d420c4` and composition GLB `981574f3…7494d30`; their 4,509,140-byte BIN chunks are exactly equal, and a sentinel-aware independent JSON comparison also finds exactly the 24 listed mesh-data `name` suffix changes. Node names, transforms, hierarchy, tags, accessors, materials, and exported geometry therefore match within that declared comparison. The suffixes are Blender mesh-data names, not node/object renames.

Two small evidence-quality improvements remain:

- `receipt/native-transfer-records.json` contains the 24 per-object source snapshots, material-slot names, transforms, and modifier records, but its hash is not included in `alignment-inventory.json` `generatedFiles` or `generationSources`. The composer source hash-binds its own inputs and outputs, yet a later edit to this useful audit record would not be detected through the inventory. Add its path/hash/size to a receipt field or a separate output-integrity manifest.
- `compare-derivatives.py` uses `dict.get()` when walking JSON keys, so a missing key and a present key with JSON `null` compare as equal. That did not hide a difference in this pair: a sentinel-aware comparison independently confirmed the reported 24 name-only differences and exact BIN equality. Still, use an explicit missing sentinel in the comparator before relying on it for another pair.

No defect was found in the declared transfer allowlist, material reassignment sequence, transform/pivot preservation checks, modifier-preserving native save, or the actual parity claim. The parity result is evidence for this composed diagnostic derivative only; it is not movement/clearance evidence, application selection, publication, or an artistic pass.
