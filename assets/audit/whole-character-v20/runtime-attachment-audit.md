## Supporting runtime facts

`presence-exhibit.js:153-160` resolves named joints and snapshots their actual rest position/rotation. `era-motion.js:45-59` derives hip, shin, foot, toe nodes, link vectors, and foot contact height from the loaded rig. Its leg solver then uses those captured link vectors (`:136-164`), so changed leg lengths are measured rather than copied from V19. Body motion also offsets from `rest.body.position` (`era-motion.js:276-281,314-320,342-344,456-480`). Keep those rest-derived paths intact while correcting mechanism mounts.

The exhibit can resolve authored `anchor-*` landmarks before using fallback offsets (`presence-exhibit.js:211-218`), which is a useful channel for maker horns, drive mounts, tail/control attachment, and review markers. Inspection opening already reads hinge-axis/angle extras from the loaded `breastplate` node (`inspection-pose.js:20-35`); V20 must preserve correct native pivot and extras through export. Its exploded offsets remain fixed local vectors at `inspection-pose.js:5-15`; they are intentional display offsets, not fitted hardware anchors.

## Priority for the V20 integration

1. Add/retain named physical anchor nodes for Maker guide eyes and horns, Mechanic paired hip-drive sockets, Advanced manifold and cervical joint sockets, and any rear/tail hinge.
2. Replace only the corresponding fixed mount coordinates with those anchors. Continue deriving live endpoints from loaded joint nodes where the code already does so.
3. Validate each attached mechanism against V20 rest bounds and representative motion poses after Sol’s model is available. This audit ran no geometry, clearance, browser, or motion tests and makes no claim that any attachment currently fits.
