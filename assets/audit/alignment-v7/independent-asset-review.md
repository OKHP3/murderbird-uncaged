# V7 independent asset review

This review checks the supplied V7 binary files, inventory declarations, source hashes, and the exported GLB’s own hierarchy and extras. It does not assess appearance, browser behavior, physical motion, artistic quality, or owner acceptance.

The native file is 1,945,914 bytes with SHA-256 `a8fccaf024a096678415215029b34cae8270b348da2301b8872a34e72c75ed3f`. The GLB is 4,426,968 bytes with SHA-256 `1c82874b86af6b493ac380536de6af72a30fafa3a4b0ebb3d8790f56ffc03018`. Both match the current V7 inventory and are actual binary files. All five entries currently listed under `generatedFiles` exist and match their declared byte lengths and SHA-256 hashes.

The inventory records the V6 native and GLB hashes and regional candidate04 source and manifest hashes. All six pinned input snapshots match their recorded hashes. All eight entries under `sourceReferences.sources` and the separate `storyAuthority` file exist locally and match their recorded hashes. The generator hash in `generationSource` matches both the copied audit script and `scripts/build-uncaged-alignment-v7.py`; the transfer’s `scriptSnapshot` carries the same hash. The generator copies `__file__` into the audit directory before composing the asset, so the record is byte-bound to that copied source. I did not find a separate process invocation log.

The inventory classifies 651 parts as inherited passive in Maker, Mechanic, and Builder; 35 as Builder-only advanced systems; and one as a Mechanic-and-Builder later repair. The GLB’s 90 mesh groups carry complete `constructionClass` and `exteriorEras` extras: 86 inherited-passive groups, three Builder-only advanced-system groups, and one later-repair group. Its hierarchy places the advanced optic beneath `builder-optics`, while the power core and processing groups are also Builder-only. Maker has no advanced-system class; Mechanic has no advanced-system class or optic system. The passive optic housing and recess remain tagged for all three active eras. These are explicit metadata claims; colors do not establish era eligibility.

The inventory contains all ten requested new guards with the expected left/right foot, shin, or thigh owners. Every one is tagged `inherited-passive` for Maker, Mechanic, and Builder. The six talon records attach to their matching left/right digit distal owners. The GLB batches these transfers into parent/era/region/role geometry groups, so the exact guard and talon object names remain visible in the inventory rather than as individual GLB node names.

The left travel-stop geometry record remains in the V7 inventory as `Original anatomical-left travel stop v4`, parented to `left-mantle`, region `shoulder`, role `frame`, and tagged passive for all three active eras. The GLB contains `left-mantle-shoulder-frame` beneath the `left-mantle` rig node with matching region, era, and passive-class extras. The original stop does not need a separate pivot: its anatomical owner is the left shoulder rig.

The runtime also retains asymmetric shoulder travel. In `src/scene/era-motion.js`, the tested thrust pose drives the left shoulder to `0.07` radians while driving the right to `-0.64` radians. The existing advanced-power-move receipt is bound to the exact V7 GLB SHA-256, passes, and asserts that the left shoulder’s absolute rotation stays below the right shoulder’s. This supports restricted left-side motion for that tested action. It does not prove a hard angular clamp, contact with the stop geometry, continuous collision behavior, or physical performance.

There is a naming weakness in the exported repair group: its name is `industrial-repairs-shoulder-repair`, while the native inventory names the source object `Proposed later left bearing strap v4`. GLB grouping omits the explicit “left” token from that repair node. The V7 inventory, left-mantle stop ownership, left-mantle hierarchy, and bounded runtime asymmetry retain the anatomical-left context; the label omission does not establish a behavioral loss.

The inventory’s carried-forward `sourceReferences` still points to the earlier review packet, including a machine-local ignored path, and remains marked as a review proposal rather than owner acceptance. Treat this as prior reference context, not a V7 approval or a portable source artifact. The separate export-comparison receipt reports 90/90 groups, 51/51 pivots, and 230,900 matching triangles. Its stated limits exclude topology/normal/UV equivalence, native object names and modifier stacks, motion, physical simulation, browser appearance, and artistic acceptance. V7 remains a neutral geometry proposal awaiting owner review.
