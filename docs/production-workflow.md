# MurderBird model production workflow

**Decision (checked 2026-09-27):** build the editable reference model in the installed local Blender 5.2.1 LTS, keep its shell plates and mechanisms as separately named objects, and export a browser GLB for the existing Vite/Three.js exhibit. Use Three.js scene code to control visibility, exploded offsets, and the cage response. This route best fits the requirement for a recognizable, mechanically plausible bird with an inspectable interior while retaining editable source and avoiding new application dependencies or asset uploads.

This is a production recommendation, not evidence that a finished model exists. Repository guidance says no finished 3D model is established. The current exhibit scene builds an illustrative bird from primitive meshes in code; `assets/models/` contains only `.gitkeep`. Keep current assets at their recorded working/draft status until a reference review accepts the result.

## Why Blender fits this exhibit

Blender provides editable mesh objects, parented parts, bones, constraints, keyframes, and scene organization. For a machine made of rigid plates, pivots, rods, and gears, use named rigid objects parented to hinge pivots rather than deforming a single bird mesh. Keep the outer shell, inner mechanism, and display cage in separately addressable collections or root groups. Add a second rig or keyed pose only where a moving joint needs it. Blender's glTF exporter supports object transforms, pose-bone and shape-key animation, materials, and GLB output; Three.js has a built-in `GLTFLoader` addon for loading the result. [Blender animation and rigging](https://docs.blender.org/manual/en/latest/animation/introduction.html) (accessed 2026-09-27), [Blender glTF exporter](https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html) (accessed 2026-09-27), [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) (accessed 2026-09-27).

Export the source scene as a `.blend` and the runtime asset as a self-contained `.glb`. Treat the GLB as a delivery copy, never the only editable source. Keep part names stable and design a small app-facing contract such as `outer_shell`, `inner_mechanism`, `head_hinge`, `bill_upper`, `bill_lower`, `wing_left`, and `wing_right`. Validate exact naming and transforms during the local experiment before coding around them. A mesh hierarchy is enough to drive a readable exploded view: Three.js can animate children away from pivots and hide selected shell meshes while preserving the source artwork and the existing scene/audio architecture.

The browser interaction should own exhibit behavior. When the user approaches, taps, or drags near the cage, animate the relevant model groups and keep the existing Web Audio engine responsible for sound. The model does not need a network service, simulation backend, new package, or continuous physics to suggest a restrained cage reaction: use a short, reversible mechanical recoil and return, with input gating to prevent repeated triggers from stacking. A future full-body rig or physics simulation is a separate scope.

## Small local experiment before full production

Use the installed, verified Blender bundle or the repository's existing Three.js package. Keep source references and outputs local; do not upload assets or call cloud image generation. A useful first probe is a single heavy hooked bill because its silhouette, hinge, and internal linkage are easy to judge against the reference.

1. In Blender, create a rough reference-faithful bill with three independently editable rigid pieces (upper shell, lower shell, and inner linkage), one hinge pivot, a visible pin or gear, and a closed/open pose. Name each object. Save a working `.blend` and export a `.glb` with the open/close action. Do not call this a finished model.
2. Load the GLB through the already-installed Three.js `GLTFLoader`. Confirm the node names, material appearance, scale, hinge pivot, and exported animation. In a temporary local harness, toggle the outer shell away to reveal the linkage, then restore it; trigger one short cage-contact recoil and settle. No new dependency is needed for this probe.
3. Inspect the GLB in the current WebGL scene and compare the silhouette and mechanical details against the user-approved reference. Confirm the illustrated fallback still communicates the same open/closed action. If the browser asset is too heavy, reduce geometry or texture resolution in the source and re-export; do not conceal quality loss by labeling the scan/model as final.

If Blender scene work is temporarily unavailable, build the same three-piece bill using existing Three.js primitives and parent groups. That fallback proves interaction and scale only; it is not a substitute for the editable authored model or a claim of reference-faithful final art.
